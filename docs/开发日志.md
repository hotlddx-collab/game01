## 2026-07-29 · 竞选 HUD 排版 + 造谣信念系统重做

### 竞选常驻 HUD 排版优化
- 与任务面板对齐：两块面板统一 `left=16 / right=400`（宽 384），不再一长一短。
- 进度条加长：`bar_min_length` 150→230，实际占宽约 232px；`score_column_width` 44→36、`name_column_width` 64，空间利用率明显提升。
- 四边留白均匀：VBox 左右 16 / 上 12 / 下 8；`row_separation` 6，两条进度条上移贴近标题，底部不再空。
- Header 取消垂直 EXPAND、改固定最小高 40，修掉首行文字被拉出面板边框的问题。
- 任务面板顶部 138→152，与竞选面板底部留 16px 间隔。
- `election_hud.gd` 改为 `@tool` + `@export` 布局参数组（面板位置/尺寸、四边内边距、行高、列宽、进度条长度、字号、间距），Inspector 可实时预览微调，`_apply_layout()` 统一应用。旧的 `_resize_panel` 按 min-size 求和的自适应逻辑与固定面板打架（是底部留白根因），已停用。

### Bug 修复：任务面板上的灰色文字
- 现象：任务面板上方叠着一行灰字「如果一直看到这条说明 → 检查 agent_server 是否启动」。
- 根因：`election_hud.gd` 的 `hint_label` 占位提示**只赋值、全代码无人隐藏**，且溢出竞选面板落到任务面板上造成重叠。该节点其余逻辑均未使用。
- 处理：清空文本并强制 `visible = false`。

### Bug 修复：造谣完全无效
- 根因在 `_infer_rumor` 的情感判定：旧代码用 `neg and not pos` 布尔互斥，而褒义词表含「好/帮/能干」等高频字，贬义句极易同时命中 → 退回 `neutral`；而 `neutral` 在后续全链（铺开条件、`election.py` 的 `sentiment IN ('smear','praise')`）都被过滤 → 零影响。更糟的是「苔老板不是好人」会被判成 `praise`，**反给对手加分**。
- 修复：
  - 新增 `_rumor_polarity()`，改用**权重计分**（贬 −2 / 褒 +2 累加）替代布尔互斥。
  - 新增 `_RUMOR_NEGATORS` 否定词表，褒义词前有「不/没/无」则极性翻转（"不好"、"没本事" 正确记为贬义）。
  - `force_smear` 兜底：走「造谣」按钮发出、文本无明显褒贬词时默认判 smear。
  - 未点名时 subject 默认指向当前竞选对手，不再误伤玩家自己。
- 验证：6 组用例，旧逻辑 3 例判错（2 例失效 + 1 例反向加分），新逻辑全对且褒义句无误伤。

### 造谣玩法重做：从「知道」到「相信」
旧机制是存量式——只要 NPC「知道」谣言就按热度扣分，导致对同一 NPC 反复造谣可**无限叠加**降分。新机制引入信念判定：

- **`db.py`**：新增 `rumor_belief` 表，主键 `(rumor_id, animal_id)`，字段 `state`(believed/rejected) / `source_id` / `score` / `judged_day`。
- **`rumor.py`**：`RumorStore` 加 `get_belief` / `set_belief`（`ON CONFLICT DO NOTHING` → 判定即锁定）/ `belief_rows_for`。
- **`belief.py`（新）**：纯数值判定，不走 LLM。
  ```
  信任分 = 亲信度(传谣者→听者) − 护主度(被造谣者→听者) + 随机扰动(±18)
  ```
  铁票护主 −45、好友背书 +20、玩家好感 ×0.6；不信则对造谣者好感 −2（造谣有社交成本）。
- **`main.py`**：
  - 造谣不再无脑铺开全镇，只对**当面这一位**做判定；NPC 回话语气随 信 / 不信 / 早已听过 而变。
  - 闲聊传播时 listener 以 speaker 为传谣者**再判一次** → 病毒式扩散，但每人只结算一次，影响上限 = 全镇人数。
  - `_judge_and_record()` 统一处理判定 + 落库 + 产出归因事件。
  - `_broadcast_election_state` 支持 `belief_events` 随包下发。
- **`election.py`**：选情分改读 `rumor_belief` 中 `state='believed'` 的记录，去掉 heat 缩放，效果可预期且有上限。

### 分数变动飘字
- `election_hud.gd` 新增 `_float_delta()` / `_reason_text()`：选情分变化时在**分数右侧**弹小字（如 `-12 小蓝信了谣言` / `+6 焰仔不信(护主)`），上浮 22px + 淡出 1.4s，绝对定位不占布局空间。

### 验证
- 去重：重复对同一 NPC 造谣仅首次结算（True→False×4），换人才新增。
- 关系比拼：好感 60 → 信谣率 100%，好感 −10 → 32%；同样高好感下铁票护主把信谣率从 100% 压到 24%。
- 后端 `py_compile` 全通过，Godot 编辑器导入无报错。

### 待办（下次）

- 对手 AI 会反制造玩家的谣，形成来回博弈。

## 2026-07-26 · 镇长玩法打磨

### 时钟
- 单个游戏日改为 15 分钟：`world_clock.gd` `time_scale = 96`（1 实秒 ≈ 1.6 游戏分，任期 4 天 ≈ 60 分钟一局）。

### GM 调试指令
- `Ctrl+G`：玩家直升当前任期现任镇长（`debug_make_mayor`），便于测试镇务玩法。
- `Ctrl+M`：强制刷新一个镇务任务（`debug_spawn_mayor_task`）。

### 镇长玩法三处 Bug 修复
1. 任务 HUD 文字溢出：`quest_hud.gd` 面板高度改为按可见内容自适应（`_resize_panel`），镇务标签 `SIZE_EXPAND_FILL` 正确换行。
2. 「讲道理 / 威胁」两种安排方式无效：根因是选项文字用了 ASCII 方括号，被 BBCode 当标签解析破坏了 `[url]`。改用全角【】；拒绝后重开选项可换方式重试。
3. NPC 领任务后无表演、无反馈：根因是 busy 状态下 `_physics_process` 不跑 intent 移动，且对话关闭的 `clear_busy` 会清掉 intent。改为对话关闭后 NPC 以自发意图走到现场，到场才置 busy 表演。

### NPC 寻路优化（防卡死）
- `approach_for_intent` 改走 `PathNetwork` 路网航点队列，绕开湖/建筑。
- `_follow_intent` 增加卡死检测 + 总超时（14s）：卡住跳航点，无航点或超时则强制到达触发回调，NPC 永不楔住。
- `PathNetwork` 新增 `random_point` / `all_waypoint_positions`，用于取可达落点。

### 造谣（放话）交互优化
- 八卦栏按钮「放话」改名「造谣」。
- 点造谣进入造谣模式：输入框占位变「谣言：…」并聚焦，回车按 `request_rumor_spread` 发出（不再当普通聊天）；发完/按 Esc 退出模式。

### 镇务情境系统（任务刷新即布置）
- `main.gd` 监听 `mayor_task_state`，任务一刷新就在世界里布置情境：
  - 打扫：全村撒 3~4 处 🤢 脏物标记，NPC 逐个走到清扫。
  - 修下水道：随机路网点生 🔧 维修标记。
  - 治疗：随机指定一名病人 NPC，挂持久 🤒 并站定；治疗者赶到身边 💊，病人痊愈。
  - 制服酒鬼：目标挂持久 🍺 并站定，执行者赶到打斗。
- `Animal.set_status_effect / clear_status_effect`：持久状态图标 + 染色，期间屏蔽普通 emote。
- 表演结束统一 `_teardown_situation` 拆除标记/状态。

### 镇务失败与选情反馈
- 治疗任务不能派病人本人（前端 `_can_assign_here` 排除 target 本人）；后端 `assign` 拒绝时返回 `executor_id`+`error`，对话框显示失败原因并重开选项。
- 镇务完成后提示选情分变化：后端 assign 前后取玩家聚合选情分，随 `mayor_task_result` 下发；左上镇务 HUD 结果行追加「声望 X→Y (+N)」，并弹中央横幅（`election_hud.flash_mayor_toast`）。`勉强了事` 无明显变化也会明确提示，确认是否生效。
