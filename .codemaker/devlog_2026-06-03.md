## 6/2 — NPC 寻路系统重写

### NavRegion 切换到 Godot 4.6 新 API

**问题**：旧 `make_polygons_from_outlines()` 报 "Convex partition failed"
- rock 层 1615 个 tile 加 4px margin → 相邻矩形重叠
- 外边界与孔洞绕向不一致
- 反复尝试无果

**解法**：彻底改用 `NavigationServer2D.bake_from_source_geometry_data()`
- `parsed_geometry_type = PARSED_GEOMETRY_STATIC_COLLIDERS`
- 自动从场景内 StaticBody2D 烘焙，无需手写 polygon
- 0 错误，0 警告

**回调修复**：lambda 里 `await` 不工作 → 改成命名方法 `_on_bake_done` + `call_deferred("_notify_npcs")`

### NPC 不动的根因

经过多轮调试，根因是 **WANDERING 状态还在用废弃的 `_nav_agent.velocity`**（设置后等 `velocity_computed` 回调），但回调被改成 `pass` 了。**速度被设但永远不会触发移动**。

修：TRAVELING + WANDERING 都直接 `velocity = ... ; move_and_slide()`。

### lack/rock 碰撞修复

- 用户手画的 lack/rock 节点没挂 ObstacleLayer 脚本 → 只有视觉没碰撞
- 自动给两个节点挂上脚本 + 推荐参数（lack 全格阻挡 / rock 逐格 30%-70%）
- ObstacleLayer 加 `merge_cells` 选项区分两种用法

### 路网坐标对齐

- `home_cui` 被用户拖到 x=-103（出地图），自动修回 (270, 530)
- 所有 home_X 节点对齐真实建筑入口（差距 ≤16px）
- 补充 bakery_door / post_door / plaza_center 节点
- 测试：`home_bear → home_fox` 路径 7 跳全经过路网节点

### 自动测试扩展（46 项）

`tests/test_npc_behavior.py` 新增两类：
- **路径沿主路验证**：A* 路径中间节点必须经过 wp_X（横向主路）
- **碰撞层配置验证**：脚本挂载 + tile 数据 + 参数合理（y_frac+h_frac≤1）

### NPC 卡屋顶问题（最终修复）

**问题**：NPC 沿主路到 (400, 350)，要去 bakery_door (400, 525)，直线南下被建筑挡住，卡在屋顶滑动

**根因**：建筑没碰撞 → NPC 穿过建筑 / 或建筑有碰撞 → NPC 撞墙不绕

**修复**：
1. **Building 自动碰撞**：building.gd `_update_collision()` 自动加 StaticBody2D（下半 90%×60%）
2. **NPC 寻路改回 NavAgent**：TRAVELING / WANDERING 优先用 `_nav_agent.get_next_path_position()`，自动绕建筑
3. **降级保护**：NavAgent 返回当前位置时回退直线
4. **卡死检测**：2 秒没移动 4 像素 → 跳过当前路径点

NavAgent 现在终于能真正发挥作用：navmesh 已包含所有 StaticBody2D（lack 湖、rock 石、buildings），自动绕过。

### 老 P01-P21 静态节点迁移

用户问："老的 P01-P21 ItemPickup 还在 Pickups 节点下，是不是还在刷？要不要也放到 ItemSpawnPoints 下？"

迁移 18 个老节点 → SP_<item>_legacy_N。**踩坑**：
1. 第一次插在 Player 节点之前，但父节点 ItemSpawnPoints 在后面声明 → "Parent path vanished" 警告
2. 修：剪切到最后一个 SP 节点之后插入
3. 仍有 P03/P10 漏迁（脚本 regex 漏匹配）→ 二次补迁

### `%Player` 全局崩溃（阴沟翻船）

迁移完成后游戏起不来，`%Player` resolution 失败。研究半天发现：我在 .tscn 里加了一行 `# ── 从 Pickups 迁移过来的生成点 ──` 注释。**Godot .tscn 不支持 `#` 注释**，导致解析跑偏，unique_name 注册表没建好。

去掉那行注释 → 立即恢复。

### 道具命名分组 + 数量均衡

用户反馈：编辑器里 SP 节点是按生成顺序排的，同类物品散落在树里不便配置。再者古书只有 1 个生成点不合理。

- 全部 SP 节点按 item_id 字母序排，统一命名 `SP_<item>_<n>`，去 _legacy 后缀
- 稀缺补点：ancient_book 1→3, bread 2→5, crystal 2→4, moonstone 2→4, resin/bark/pearl 4→5
- 总 SP 131 → 143

## 6/3 晚 — 任务系统 v2 重构

用户测试发现：
- 焰仔接到送信任务后**立即完成**（玩家根本没动），原因是判定用了任务前的历史
- 给小翠送 4 朵野花后**没完成**（送礼路径不调 quest 检查 + 背包归零）

### 重新设计 3 类任务

| 类型 | 字段 | 完成判定 |
|---|---|---|
| collect | item_id, count | progress（送礼累计）+ 背包 ≥ count → 找委托人 chat 完成 |
| relay | target_npc, message_summary, keywords[] | chat target_npc 时 user_text 命中所有 keywords |
| deliver | target_npc, item_id, count | 接受时服务端 push 物品到背包 → chat target_npc 完成 |

### 关键修复

- DB schema v3：增加 `progress` 字段（送礼累计计数）
- `agent.receive_gift()` 末尾调 `_advance_collect_by_gift()` → 物品匹配 progress+1，达标即完成（不二次扣）
- chat 路径完成判定改为 `progress + 当前背包 ≥ count`，超出从背包扣
- 接受 + 完成不再同回合发生（接受后立即返回）
- `quests.json` 12 个任务全部按新 schema 重写：6 collect + 3 relay + 3 deliver
- 旧 schema 任务自动迁移为 abandoned

### UI 强化

- 新增 **QuestHUD**（左上角持续显示当前任务，含 collect 进度 X/N）
- 接受任务时对话框 📜 横幅，含完整指引（要做什么 / 物品 / 目标 NPC）
- 完成时显示交付/奖励明细
- 协议层 `quest_offer` / `quest_progress` / `quest_completed` 字段大扩
